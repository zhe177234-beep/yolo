# 部署说明

## GitHub 与运行服务

仓库保存全部源代码、安装步骤、模型准备脚本、训练入口、Docker 和持续集成。权重/原始上传/结果/密钥不提交 Git。GitHub Actions 验证项目，GitHub 本身不会持续运行检测服务。

单机部署使用 README 中的 Python 或 Docker Compose 命令。部署前至少 4 GB 可用内存，并留出 PyTorch、模型和上传数据磁盘空间；实际需求随输入分辨率、依赖平台和负载变化。

## 公网部署

在支持 Docker 的 Linux 主机克隆仓库，创建 `.env` 并设置强随机 `YOLO_API_KEY`，运行 `docker compose up -d --build`。Compose 默认仅发布到回环地址；将 HTTPS 反向代理指向 `127.0.0.1:8000`。浏览器在“访问密钥”中输入该密钥，密钥仅保存在当前标签页 sessionStorage。

反向代理设置上传请求上限，例如 Nginx `client_max_body_size 101m`；视频异步执行，上传接口返回后通过轮询获取结果。按需求限制上传速率与客户端连接数。任务 API 和下载均需要 `X-API-Key`；健康接口公开最小运行状态，不含密钥。

保持 **一个 Uvicorn worker、一个服务实例**。内存任务队列不能跨进程共享，启动时会标记旧任务失败；多实例应先引入独立任务队列与对象存储，不能直接增加 `--workers`。队列最多容纳 8 个任务；视频每一帧都会推理，CPU 下长视频处理可能明显慢于播放时长。

原始上传在完成/失败后删除；重启时也会清理中断任务的原文件。SQLite 和导出文件会保留直到用户删除，需监控磁盘、安排备份和按保留策略清理。任务执行期间禁止删除。输出视频为 H.264、无音轨；前端用首帧预览，完整标注视频下载后播放。

## GPU

本仓库 Dockerfile 固定为 CPU 部署以减少首次运行门槛。GPU 部署需要匹配驱动的 CUDA 版 PyTorch、NVIDIA Container Toolkit，并将 `YOLO_DEVICE=0`。这是配置扩展入口，本项目没有在 GPU 机器上实测。

## 故障排查

| 现象 | 处理 |
| --- | --- |
| 模型不存在 | 在项目根目录运行 `python scripts/setup_model.py`，或检查 `YOLO_MODEL` |
| 下载失败 | 检查对 GitHub 官方资产地址的访问；可管理员手动下载可信权重 |
| 401 | 检查浏览器/API 的密钥与服务环境变量一致 |
| 413 / 429 | 缩小文件，或等待队列完成 |
| 视频失败 | 查看 `docker compose logs studio`，确认格式可解码、长度 ≤60 秒 |
| 服务重启后任务失败 | 重新上传；已完成结果仍保留 |
| 检测不到自定义目标 | COCO 不包含该类别；训练自定义 detect 模型 |

## 自动化验证

每次推送到 main 或发起 PR，CI 执行代码静态检查、接口测试和真实样图/短视频推理，并单独验证容器构建与启动。模型下载依赖外网，下载故障也会导致 CI 失败，日志会标明阶段。
